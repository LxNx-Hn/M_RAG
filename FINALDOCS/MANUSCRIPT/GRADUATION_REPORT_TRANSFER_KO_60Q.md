# 1. 서론 [스타일=장(1.)]

## 1.1 연구배경 및 목적 [스타일=절(1.1)]

검색 증강 생성(Retrieval-Augmented Generation, RAG)은 질문과 관련된 문서 구간을 외부 자료에서 검색하고, 검색한 구간을 생성 모델의 입력에 넣어 답변을 만드는 방법이다[1]. RAG는 모델의 학습 시점 이후에 나온 논문과 기술 문서도 원문을 근거로 답할 수 있어 학술 문서 질의응답에 널리 쓰인다.

RAG의 성능을 높이는 기법은 검색 단계와 생성 단계에 모두 있다. 검색 단계의 가상 문서 임베딩(Hypothetical Document Embeddings, HyDE)은 질문에 대한 답변 형태의 가상 문서를 먼저 생성하고, 이 문서의 임베딩으로 실제 문서를 검색한다[2]. 생성 단계의 문맥 인식 디코딩(Context-Aware Decoding, CAD)은 검색 결과를 입력에 포함했을 때와 제외했을 때의 다음 토큰 점수를 비교하여, 검색 결과가 뒷받침하는 토큰이 선택될 가능성을 높인다[3]. 소프트 제약 디코딩(Soft Constrained Decoding, SCD)도 생성 단계에서 목표 언어 토큰과 다른 언어 토큰의 로짓에 서로 다른 계수를 곱해 출력 언어를 제어한다[4].

한국어 질의로 영어 논문을 다루는 RAG는 세 가지 과제를 함께 풀어야 한다. 검색에서는 한국어 질의와 영어 원문의 어휘 차이를 넘어 근거를 찾아야 하고, 답변 생성에서는 영어 근거의 내용을 한국어 답변에 충실히 반영해야 한다. 또한 모델이 영어 근거를 따라 영어로 답하는 언어 이탈(language drift)을 막아야 한다. 앞의 세 기법은 이 과제에 하나씩 대응한다. HyDE는 검색 입력을, CAD는 근거 반영을, SCD는 출력 언어를 조정한다. 세 기법의 원 논문은 각기 다른 모델과 과제에서 검색 입력, 문맥 반영, 출력 언어를 평가하였다. 본 연구에서는 같은 파이프라인과 한국어 질문에 세 기법을 적용하고, 질문 유형과 요구 정보에 따른 답변·검색 점수와 실행 시간을 비교한다.

실험에는 영어 학술·기술 문서를 검색하여 한국어 답변을 생성하는 고정 파이프라인 Paper-RAG를 사용하였다. 같은 한국어 질문 60개에 HyDE·CAD·SCD의 여덟 적용 조건을 구성하였다(그림 1-1).

## 1.2 연구범위 [스타일=절(1.1)]

검색 대상은 영어 문서 4종으로, RAG Survey[D1], CAD[D2], RAPTOR[D3], Mi:dm K 2.5 Pro Technical Report[D4]이다. 문서마다 한국어 질의를 15개씩, 총 60개 작성하였고, 각 질의의 검색 범위는 해당 문서로 한정하였다. 질의마다 8개 조합을 적용하여 생성 답변 480개를 얻었다.

답변 생성 모델은 Mi:dm 2.0 Base Instruct[M1]이다. 검색·생성 품질은 RAGAS의 네 지표로, 출력 언어는 한국어 문자 비율로, 비용은 조합별 실행 시간으로 측정하였다. 검색·재정렬·생성 설정은 4장에 정리하였다.

## 1.3 연구 질문 및 논문 구성 [스타일=절(1.1)]

연구의 중심 질문은 ‘한국어 질의로 영어 문서를 다루는 RAG에서 질문의 유형과 특성에 따라 HyDE·CAD·SCD의 결과가 어떻게 달라지는가?’이다. 이를 다음 네 연구 질문(research question, RQ)으로 나누었다.

## 2.2 하이브리드 검색과 재정렬 [스타일=절(1.1)]

밀집 검색은 질의와 문서 구간을 임베딩한 벡터의 유사도로, BM25 희소 검색은 두 텍스트의 어휘 일치로 관련 구간을 찾는다[5][6]. 한국어 질의와 영어 원문은 어휘가 대부분 다르지만, 논문명·모델명·데이터셋명·수치처럼 두 언어에 같은 형태로 쓰이는 표기는 BM25의 검색 단서가 된다.

두 검색 결과는 가중 역순위 융합(weighted Reciprocal Rank Fusion, RRF)으로 결합한다[7]. 문서 d의 밀집 검색 순위와 BM25 순위를 각각 rank_dense(d), rank_BM25(d)라 할 때, 가중치 0.6과 0.4, 상수 k=60을 적용한 결합 점수는 다음과 같다.

[한글 수식 입력기 복붙용 — 최종 HWP에는 렌더링된 수식만 남김]

```text
RRF(d) = {0.6} over {k + rank_dense(d)} + {0.4} over {k + rank_BM25(d)}
```

융합한 검색 후보는 질의와 후보 구간을 한 쌍으로 입력받는 재정렬 모델의 관련성 점수로 다시 정렬한다. 재정렬 모델로는 문맥화된 언어 모델 표현을 문서 순위 계산에 활용한 CEDR[8] 등이 있다. 재정렬 순서는 생성 모델에 입력하는 검색 결과의 배치를 정한다. 생성 모델은 입력 내 위치에 따라 근거를 다르게 활용할 수 있으므로[9], 이 배치가 답변에도 영향을 줄 수 있다.

## 2.4 Context-Aware Decoding [스타일=절(1.1)]

CAD는 검색 결과를 포함했을 때와 제외했을 때의 다음 토큰 로짓을 가중 결합하는 디코딩 방법이다. 검색 결과를 넣었을 때 로짓이 크게 오르는 토큰일수록 검색 결과의 영향을 많이 받는다. CAD는 두 로짓의 차이를 키워, 모델의 사전 지식보다 검색 결과의 내용을 반영하는 토큰이 선택되도록 한다(그림 2-3).

지금까지 생성한 토큰열을 동일하게 두고, 검색 결과를 포함한 입력의 로짓을 z_ctx, 제외한 입력의 로짓을 z_noctx라 하면 CAD의 로짓은 다음과 같다. α는 검색 결과의 영향을 키우는 정도를 정하며, α=0이면 일반 디코딩과 같다.

[한글 수식 입력기 복붙용 — 최종 HWP에는 렌더링된 수식만 남김]

```text
z_CAD = (1 + alpha) z_ctx - alpha z_noctx
```

Shi 외는 요약 과제와 지식 충돌 과제(모델의 사전 지식이 입력 문서의 내용과 충돌하는 과제)에서 CAD가 입력 문서를 더 충실히 반영한다고 보고하였다. CAD는 토큰마다 검색 결과를 제외한 입력의 로짓을 한 번 더 계산하므로 생성 시간이 늘어난다.

## 2.5 Soft Constrained Decoding과 언어 이탈 [스타일=절(1.1)]

다국어 RAG에서는 질문과 다른 언어의 문서를 검색하면 답변이 검색 문서의 언어로 바뀌는 언어 이탈이 발생할 수 있다. Li 외는 이 현상을 분석하고, 디코딩 단계에서 목표 언어 토큰의 점수를 조정하는 SCD를 제안하였다. SCD는 어휘 집합을 목표 언어 토큰, 비목표 언어 토큰과 숫자·기호 같은 중립 토큰으로 나누어 로짓을 조정한다(그림 2-4).

[그림삽입: FINALDOCS/FIGURES/LITERATURE/fig2_4_scd_independent.png | 권장폭=본문폭 75% | 정렬=가운데]

[그림 2-4] SCD의 토큰 그룹별 로짓 조정[4] [스타일=그림제목]

생성한 토큰 수가 Tstart 이상이 되면 목표 언어 토큰의 로짓 z_i에는 α를, 비목표 언어 토큰의 로짓에는 β를 곱하고, 중립 토큰은 그대로 둔다. 아래 식의 좌변은 조정된 로짓이다. 본 연구는 한국어를 목표 언어로 하여 원 논문의 곱셈식을 그대로 적용하였다. 이 식은 원시 로짓에 계수를 곱하므로, 로짓이 양수인 토큰과 음수인 토큰에서 점수가 변하는 방향이 반대가 된다.

[한글 수식 입력기 복붙용 — 한국어 목표 토큰]

```text
tilde z_i = alpha z_i
```

[한글 수식 입력기 복붙용 — 비목표 언어 토큰]

```text
tilde z_i = beta z_i
```

[한글 수식 입력기 복붙용 — 중립 토큰]

```text
tilde z_i = z_i
```

## 2.6 RAG 평가 [스타일=절(1.1)]

RAGAS(Retrieval Augmented Generation Assessment)는 RAG의 검색과 생성을 나누어 자동으로 평가하는 프레임워크다[10]. RAGAS가 제공하는 근거 충실도(faithfulness), 답변 관련성(answer relevancy), 문맥 정밀도(context precision), 문맥 재현율(context recall) 가운데 근거 충실도와 답변 관련성은 생성 답변을, 문맥 정밀도와 문맥 재현율은 검색 결과를 평가한다. 근거 충실도는 평가 모델로 쓰는 대규모 언어 모델(Large Language Model, LLM)이 답변을 주장 단위로 나누고 각 주장이 검색 결과에 근거하는지 판정하여 계산한다. 지표별 계산 방식은 5.2절에 정리하였다.

## 2.7 관련 연구와 본 연구의 위치 [스타일=절(1.1)]

# 3. 시스템 설계 [스타일=장(1.)]

## 3.1 연구 및 실험 요구사항 [스타일=절(1.1)]

모든 조합에서 검색·재정렬·생성 모델, 청크 분할, 후보 수의 상한과 생성 설정을 고정하고, 같은 한국어 질의 60개를 사용하였다. 질의마다 검색 결과, 생성 답변, 실행 시간과 파라미터를 저장하여 조합 간 결과를 질의 ID로 연결하였다.

## 3.2 아키텍처 설계 [스타일=절(1.1)]

Paper-RAG는 검색, 재정렬, 생성의 세 단계로 구성되며, 실행 순서는 4.2절의 그림 4-1에 제시하였다. 검색 단계에서는 BGE-M3 기반 밀집 검색과 BM25 희소 검색을 함께 사용한다. HyDE는 밀집 검색의 입력만 원질의에서 영어 가상 문서로 바꾸고, BM25와 재정렬에는 항상 한국어 원질의를 사용한다.

두 검색 결과를 가중 RRF로 결합하고 CrossEncoder로 재정렬한 뒤, 상위 5개 구간을 생성 모델에 입력한다. 생성 단계에서는 검색 결과 유무에 따른 원래 로짓의 차이를 쓰는 CAD를 먼저 적용하고, SCD는 CAD가 결합한 로짓에 언어별 계수를 곱한다. 두 기법은 생성 단계에만 작용하므로, HyDE 미적용 조합에서 CAD와 SCD의 적용 전후 비교에는 같은 검색 결과가 쓰인다.

## 3.3 실험 조건과 질문별 대응 비교 [스타일=절(1.1)]

HyDE·CAD·SCD의 적용 여부를 조합한 여덟 조건을 사용하였다. 조건 번호는 1 미적용, 2 CAD, 3 HyDE, 4 HyDE+CAD, 5 SCD, 6 CAD+SCD, 7 HyDE+SCD, 8 HyDE+CAD+SCD이다. 모든 조건에 같은 60개 질문을 입력하여 480개 생성 기록을 얻었다. 각 기법의 파라미터와 공통 모델은 4장에 정리하였다.

품질 지표는 영어 검색 근거로 평가한 조건 1~4 안에서, 한국어 번역 근거로 평가한 조건 5~8 안에서 비교한다. 한국어 문자 비율과 실행 시간은 여덟 조건에서 직접 측정한 값을 사용한다. 대응 비교는 질문 ID로 연결하며, 질문 유형은 사실 및 정의, 방법 및 절차, 결과 및 비교, 목적 및 기여의 네 분류를 유지한다.

미적용에서 CAD를 적용한 비교와 SCD에서 CAD+SCD를 적용한 비교는 60개 모두 입력 문서 구간이 같다. HyDE에서 HyDE+CAD를 적용한 비교와 HyDE+SCD에서 세 기법을 적용한 비교는 입력 문서 구간이 같은 질문이 각각 18개와 24개다. 각 조건에서 저장된 가상 문서와 검색 결과가 달라진 질문을 포함하므로, 후자의 차이는 검색 변화가 함께 포함된 조합 간 관측 차이로 해석한다.

# 5. 실험 [스타일=장(1.)]

## 5.1 질문 구성과 분석 대상 [스타일=절(1.1)]

실험은 네 영어 문서에 관한 한국어 질문 60개를 대상으로 하였다. RAG Survey, CAD, RAPTOR, Mi:dm K 2.5 Pro Technical Report에서 문서마다 15개 질문을 구성하고, 각 질문에 여덟 조건을 적용하여 480개 답변을 생성하였다. 질문별 검색 범위는 지정된 한 문서다.

문서별 초기 질문 3개와 주요 내용 15개 단위의 요약을 바탕으로 질문을 작성하고, 연구자가 원문에서 답변 가능성과 정답 근거의 페이지를 확인하였다. 초기 질문은 문서별 15개에 포함된다. 문서 기반 질문의 작성과 근거 확인에는 QASPER[21]와 질문 생성 연구[22]의 절차를 참고하였다. 부록 A에 질문 원문과 정답 근거를 제시하였다.

질문은 사실·정의 8개, 방법·절차 29개, 결과·비교 20개, 목적·기여 3개다. 사실·정의는 개념이나 조건의 의미를, 방법·절차는 구조와 처리 방법을, 결과·비교는 성능 수치와 차이를, 목적·기여는 연구의 목적과 이점을 묻는다. 예를 들어 최적 클러스터 수의 결정 방법은 방법·절차에, 서로 다른 검색 계층의 성능 수치는 결과·비교에 속한다. 목적·기여의 평균은 세 질문의 값으로 계산하였다.

분류는 질문의 내용과 정답 근거를 전수 대조하여 확인하였다. 답 형태는 서술형 42개와 수치형 18개이며, 한 질문에서 요구한 항목 수도 함께 기록하였다. 질문의 유형, 답 형태, 요구 항목은 서로 다른 특성이다. 모델의 명칭을 묻는 방법 질문과 정성적인 차이를 묻는 결과 질문도 포함된다. 유형별 비교에는 이 구성을 그대로 사용하였다.

## 5.2 평가 지표와 평가 입력 [스타일=절(1.1)]

평가는 답변의 내용, 검색된 근거, 출력 언어와 처리 시간을 대상으로 한다. RAGAS 0.2.15의 근거 충실도·답변 관련성·문맥 정밀도·문맥 재현율은 GPT-4o 평가 모델과 BGE-M3 임베딩으로 계산하였다. 참조 답변은 부록 A의 영어 정답 근거다.

근거 충실도는 생성 답변의 주장 가운데 입력 문서 구간이 뒷받침하는 비율이다. 답변 관련성은 생성 답변에서 역으로 만든 질문과 원질문의 임베딩 코사인 유사도를 바탕으로 계산한다. RAGAS는 답변을 모호하거나 회피적인 응답으로 판정하면 관련성을 0으로 계산한다. 따라서 관련성 분석에서는 0점에서 양수로 바뀐 질문과 실제 답변의 내용을 함께 확인하였다.

문맥 정밀도는 참조 답변에 유용한 검색 구간이 상위에 배치되는 정도이며, 문맥 재현율은 참조 답변의 주장을 검색 결과가 뒷받침하는 비율이다. 충실도·정밀도·재현율은 0~1이고, 관련성의 이론적 범위는 −1~1이다. 이번 관련성 관측값은 모두 0~1이었다. 네 지표는 높을수록 각각의 평가 기준에서 높은 점수다.

한국어 문자 비율은 생성 답변의 한글 문자 수를 한글 문자 수와 ASCII 영문자 수의 합으로 나눈 값이다.

```text
KoreanRatio = {N_Hangul} over {N_Hangul + N_ASCII}
```

N_Hangul은 한글 문자 수이고 N_ASCII는 ASCII 영문자 수다. 모델명과 논문명에 쓰인 영문자도 집계한다. 숫자만 반복한 출력 한 건은 원래 측정 기록에 비율 0으로 저장되어 있다. 비율 차이 0.20은 20%p다. 실행 시간은 질문 처리의 시작부터 답변 생성과 메타데이터 구성까지의 초 단위 기록이며, 짧을수록 처리 비용이 작다.

품질 평가에 제공한 근거의 언어는 SCD 상태에 따라 달랐다. SCD를 적용하지 않은 조건 1~4는 영어 검색 결과로 평가했고, SCD를 적용한 조건 5~8은 같은 실행에서 저장한 검색 결과를 한국어로 번역하여 평가하였다. 답변 생성 단계의 근거와 두 평가 묶음의 참조 답변은 모두 영어였다. 품질 표는 각각 같은 평가 언어의 기준 조건과 적용 조건을 대응시킨 결과다.

## 5.3 질문별 대응 비교 방법 [스타일=절(1.1)]

분석은 같은 질문에서 적용 조건의 점수로부터 기준 조건의 점수를 빼는 방식으로 수행하였다. 유형별로 같은 유효 질문의 기준 평균과 적용 평균, 평균 변화량을 계산하였다. 점수 차이가 0.05보다 크면 개선, −0.05보다 작으면 악화, 두 경계를 포함한 사이는 비슷함으로 집계하였다. 시간 변화는 1초를 경계로 증가·감소·비슷함을 구분하였다.

영어 근거 평가에서는 미적용에 HyDE 또는 CAD를 적용한 비교와, HyDE 또는 CAD에 나머지 기법을 추가한 비교를 수행하였다. 한국어 번역 근거 평가에서는 SCD에 HyDE 또는 CAD를 더한 비교와, HyDE+SCD 또는 CAD+SCD에 나머지 기법을 추가한 비교를 수행하였다. 한국어 문자 비율은 네 HyDE·CAD 설정에서 SCD 추가 전후를 대응시켰다.

근거 충실도 480개 가운데 결측은 5개였다. CAD의 두 질문과 SCD의 세 질문에서 발생하였으며, 해당 대응 비교의 두 평균을 계산할 때 같은 질문을 함께 제외하였다. 질문 유형과 비교 조건에 따라 표의 유효 질문 수가 달라지는 이유다. 나머지 지표의 480개 값은 모두 저장되어 있었다.

유형 평균의 변화를 확인한 뒤 큰 변화에 속한 질문, 같은 유형의 반대 사례와 문서별 구성을 조사하였다. 실제 사례는 이 분석에서 발견한 근거 확보, 답변 형식의 변화, 수치 누락과 자동 점수의 불일치를 설명하도록 선정하였다. 사례마다 원문 정답 근거, 실제 입력 구간과 생성 답변을 대조하였다.

## 5.6 질문이 요구한 정보와 실제 답변 [스타일=절(1.1)]

방법·절차 질문의 관련성 상승에는 필요한 설명을 새로 검색한 경우와 같은 근거를 더 잘 설명한 경우가 함께 있었다. RAPTOR에서 BIC가 결정하는 항목을 묻는 질문은 HyDE 적용 후 최적 클러스터 수를 정한다는 구간을 입력받았고, 답변에도 그 내용을 제시하였다. 관련성은 0.000에서 0.895로, 재현율은 0.000에서 1.000으로 바뀌었다. NQ-Swap의 생성 절차를 묻는 질문은 두 조건 모두 정답 구간을 입력받았다. 미적용의 출력은 절별 설명을 요청하는 문장들이었고, HyDE의 출력은 개체 정답 질문 선택·근거 문서 탐색·정답 개체 치환의 세 단계였다.

관련성이 양수로 바뀐 질문 중에는 다른 주제의 원문을 이어 쓴 답변도 있었다. Fusion SFT에서 non-reasoning 데이터의 비중을 늘린 목적을 묻는 질문의 HyDE 답변은 사전학습 단계의 데이터 구성을 영어로 설명하였다. 요구된 정보는 대화 정렬이라는 목적과 창작·번역·일반 질의응답의 보강이었고, 기록된 관련성은 0.000에서 0.463으로 바뀌었다. 이 사례는 유형 평균의 상승을 구성한 답변의 내용을 보여준다.

수치 비교 질문에서는 필요한 표의 값과 답변이 옮긴 행을 확인하였다. QuALITY의 한 계층과 세 계층 성능을 묻는 질문은 미적용의 입력 구간과 답변에 57.9와 73.68이 모두 있었다. HyDE 적용 후 73.68을 담은 구간이 빠졌고 답변은 일반적인 전체 트리 검색의 장점 설명으로 바뀌었다. 관련성은 0.871에서 0.000으로, 재현율은 1.000에서 0.000으로 낮아졌다.

LLaMA-30B의 XSUM 결과를 묻는 질문은 같은 입력 구간에서도 표의 다른 행을 답하였다. 정답은 ROUGE-L 18.7·22.0, factKB 47.7·66.4, BERT-P 87.1·90.3이었다. 미적용과 CAD 답변은 다른 행의 ROUGE-L 25.8·31.8과 factKB 87.8을 XSUM 값으로 제시하였다. CAD 적용 후 근거 충실도는 0.526에서 0.867로 바뀌었다. 높은 충실도와 잘못 옮긴 표의 행이 함께 기록된 경우다.

CAD가 다른 내용의 답변을 생성한 사례도 있었다. RAPTOR의 청크 길이와 문장 경계 처리를 묻는 질문에서 미적용은 설명을 요청하는 문장을 반복했고 CAD는 트리 구축 비용의 선형 증가를 설명하였다. 질문의 정답 근거는 100토큰 청크와 다음 청크로 문장을 옮기는 규칙이었다. 기록된 충실도는 0.250에서 1.000으로, 관련성은 0.000에서 0.755로 바뀌었다. RAG의 지식 집약 과제 이점을 묻는 질문에서는 미적용의 지식 갱신 설명이 CAD 적용 후 ‘위 내용 참조’라는 짧은 지시문으로 바뀌었다. 관련성은 0.900에서 0.000으로, 시간은 22.6초에서 4.0초로 바뀌었다.

복수 기법 비교에서는 입력 구간의 변화와 출력 주제의 이동을 함께 확인하였다. Naive RAG의 과정을 묻는 질문은 HyDE와 HyDE+CAD 모두 색인·검색·생성의 세 단계를 담은 구간을 입력받았다. 가상 문서를 다시 생성한 뒤 최종 다섯 구간 중 하나가 바뀌었고, HyDE+CAD 답변은 Modular RAG의 새 모듈을 묻는 질문을 스스로 만든 뒤 그 내용을 설명하였다. 관련성은 0.929에서 0.000으로 낮아졌다. 부록 B에는 이 절에서 설명한 질문의 정답 근거와 필요한 답변 발췌를 정리하였다.

## 5.8 질문 구성과 적용 조건에 대한 논의 [스타일=절(1.1)]

기법을 결합한 조건에서는 답변 관련성이 낮아진 질문이 더 많았다. 답변 관련성에서 개선이 악화보다 많은 비교는 모두 HyDE를 추가한 비교였고, CAD를 추가한 네 비교는 모두 악화가 더 많았다. 근거 충실도는 CAD를 추가한 비교에서도 개선과 악화의 수가 비슷하였다. 한국어 문자 비율은 SCD를 포함한 네 조건이 모두 0.699 이상으로 SCD 미적용 조건(0.488~0.556)보다 높았으며, HyDE+SCD가 0.807로 가장 높았다. 따라서 조합의 이점이 분명한 경우는 한국어 출력이 필요할 때 SCD를 더하는 경우였다.

질문 유형에 따라 유리한 기법이 달랐다. 방법·절차 질문에서는 HyDE가 두 평가 언어 모두에서 관련성을 높였다. 이 상승은 RAPTOR·Mi:dm·RAG Survey의 방법·절차 질문에서 각각 +0.306, +0.205, +0.168로 나타났고 CAD 문서에서는 −0.012였다. 수치를 묻는 결과·비교 질문에서는 HyDE의 평균 변화가 작았고, 정답 수치가 담긴 구간의 확보와 답변이 옮긴 표의 행이 결과를 좌우하였다. 목적·기여는 세 질문이어서 한 질문의 변화가 평균을 크게 바꾸었다.

자동 점수와 실제 답변은 함께 읽어야 한다. CAD의 충실도가 오른 XSUM 답변은 다른 행의 수치를 옮겼고, RAPTOR 청크 질문의 CAD 답변은 질문과 다른 내용을 설명하였다. 같은 입력 구간에서 ‘정보를 확인할 수 없다’고 답한 BIC 질문의 미적용 답변은 관련성 0.000, CAD 답변은 0.890으로 기록되었다. 60개 질문은 모두 대상 문서의 명시적 내용으로 답하는 질문이다. CAD가 설계된 지식 충돌 상황의 효과는 허위 전제나 사전 지식과 충돌하는 질문 그룹을 구성하여 비교할 수 있다.



# 6. 결론 [스타일=장(1.)]

## 6.1 연구 질문별 결과 [스타일=절(1.1)]

RQ1. HyDE는 방법·절차 질문의 답변 관련성을 영어 근거 평가에서 +0.172(개선 14개, 악화 3개), 한국어 번역 근거 평가에서 +0.157 높였다. 상승의 상당 부분은 관련성 0점에서 양수로 바뀐 여섯 질문에서 나왔다. CAD는 입력 구간이 같은 상태에서 충실도를 전체 +0.029 바꾸었고 관련성은 −0.007로 비슷하였다(표 5-1, 5-2).

RQ2. CAD를 더한 조합은 관련성을 낮춘 질문이 높인 질문보다 많았다. HyDE에 CAD를 더하면 개선 7개, 악화 22개였고 HyDE+SCD에 CAD를 더하면 개선 7개, 악화 18개였다. HyDE가 포함된 조합 비교에는 다시 생성된 가상 문서로 바뀐 입력 구간이 함께 반영되었다(표 5-3).

RQ3. SCD는 네 HyDE·CAD 설정에서 한국어 문자 비율을 +0.205~+0.251 높였고, 60개 중 50~56개 질문에서 0.05를 넘게 증가시켰다. 처리 시간은 CAD가 미적용보다 평균 43.1초 길었고, SCD 단독의 평균 차이는 −1.9초였다(표 5-5, 5-6).

RQ4. 실제 질문 대조에서는 필요한 구간의 회복, 비교 수치의 누락, 다른 표 행의 인용, 질문과 다른 내용의 설명을 확인하였다. 높은 충실도나 관련성이 요구 정보의 제시와 일치하지 않는 답변도 있었다(5.6절, 부록 B).

## 6.2 연구의 의의와 적용 조건 [스타일=절(1.1)]

이 연구는 같은 검색·생성 파이프라인에서 HyDE·CAD·SCD의 여덟 조건을 질문 유형별로 비교하고, 점수 변화를 실제 검색 구간과 답변으로 확인하였다. 관측 결과에 따른 적용 조건은 다음과 같다. 방법·절차를 묻는 질문에는 HyDE를 적용한다. 한국어 답변이 필요하면 SCD를 더한다. 수치를 묻는 질문은 정답 수치가 담긴 구간이 입력되었는지 확인한다. CAD는 평균 43.1초의 추가 시간에 비해 관련성 변화가 작았으므로, 문서와 사전 지식이 충돌하는 질문에서 별도로 검토한다.

## 6.3 후속 연구 [스타일=절(1.1)]

이번 결과는 영어 문서 네 종, 한국어 질문 60개, 생성 모델 한 종에서 질문·조건별로 한 번 생성하고 평가한 기록이다. 다음 실험은 문서·유형별 질문 구성의 균형, 반복 생성·평가와 사람의 요구 항목 검토를 중심으로 확장할 수 있다. 허위 전제나 지식 충돌을 담은 질문을 별도 그룹으로 구성하면 문서 근거를 따르는 정도를 CAD와 함께 비교할 수 있다. 번역 단독 검색과 고정 가상 문서를 적용한 조건은 검색 입력 변경과 생성 제어를 각각 비교하는 데 사용한다. 수치·인용의 정확성과 한국어 자연스러움을 함께 확인하면 이번 질문별 관측을 더 넓은 문서와 생성 모델에서 검토할 수 있다.

기준 조건은 HyDE, 적용 조건은 HyDE+CAD이다. 두 조건 모두 첫 입력 구간에 색인·검색·생성의 세 단계가 있었고, 가상 문서가 다시 생성되어 다섯 구간 중 하나가 바뀌었다. HyDE 답변은 세 단계를 설명하였고, HyDE+CAD 답변은 입력 구간을 이어 쓴 뒤 Modular RAG의 새 모듈을 묻는 질문을 스스로 만들어 그 내용을 설명하였다.

기준 답변 발췌: ‘1. Indexing(색인화)’ / ‘2. Retrieval(검색)’ / ‘3. Generation(생성)’

적용 답변 발췌: ‘Modular RAG 패러다임에서 새롭게 도입된 모듈들은 무엇이며’ / ‘Modular RAG 프레임워크에서 가장 주목할 만한 혁신 중 하나는 Search Module의 도입입니다.’

답변 관련성: 0.929 → 0.000 (차이 -0.929). 근거 충실도: 0.950 → 0.733 (차이 -0.217). 

## B.9 큰 청크와 작은 청크의 장단점 [스타일=절(1.1)]

질문: ‘RAG에서 큰 청크와 작은 청크를 사용할 때 각각 어떤 장단점이 발생합니까?’

정답 근거: RAG Survey 원문 8쪽의 ‘Larger chunks can capture more context, but they also generate more noise; smaller chunks may not fully convey the necessary context, but have less noise.’이다.

기준 조건은 미적용, 적용 조건은 SCD이다. 두 답변 모두 질문한 장단점을 설명하지 않았다. 미적용 답변은 참고문헌 목록을 이어 쓴 뒤 RAG의 세 구성요소를 한국어로 설명하였고, SCD 답변은 영어 참고문헌만 이어 써서 한국어 문자 비율이 0.425에서 0.000으로 낮아졌다.

기준 답변 발췌: ‘따라서 RAG의 세 가지 핵심 구성요소는 Retrieval(검색), Generation(생성)’

적용 답변 발췌: ‘few examples,” arXiv preprint arXiv:2305.06296, 2023. [7] P. Lewis, E. Perez, A. Piktus, F. Petroni, V. Karpukhin, N. Goyal, H. K¨uttler, M. Lewis, W.’

한국어 문자 비율: 0.425 → 0.000 (차이 -0.425).
