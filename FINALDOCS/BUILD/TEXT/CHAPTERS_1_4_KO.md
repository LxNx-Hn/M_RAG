# 1. 서론 [스타일=장(1.)]

이 장은 연구 배경과 목적, 연구 범위, 연구 질문을 제시한다.

## 1.1 연구배경 및 목적 [스타일=절(1.1)]

검색 증강 생성(Retrieval-Augmented Generation, RAG)은 질의와 관련된 문서 구간을 외부 자료에서 검색하고, 검색한 구간을 생성 모델의 입력에 넣어 답변을 만드는 방법이다[1]. RAG는 모델의 학습 시점 이후에 나온 논문과 기술 문서도 원문을 근거로 답할 수 있어 학술 문서 질의응답에 널리 쓰인다.

RAG의 성능을 높이는 기법은 검색 단계와 생성 단계에 모두 있다. 검색 단계의 가상 문서 임베딩(Hypothetical Document Embeddings, HyDE)은 질문에 대한 답변 형태의 가상 문서를 먼저 생성하고, 이 문서의 임베딩으로 실제 문서를 검색한다[2]. 생성 단계의 문맥 인식 디코딩(Context-Aware Decoding, CAD)은 검색 결과를 입력에 포함했을 때와 제외했을 때의 다음 토큰 점수를 비교하여, 검색 결과가 뒷받침하는 토큰이 선택될 가능성을 높인다[3]. 소프트 제약 디코딩(Soft Constrained Decoding, SCD)도 생성 단계에서 목표 언어 토큰과 다른 언어 토큰의 로짓(소프트맥스 적용 전의 토큰 점수)에 서로 다른 계수를 곱해 출력 언어를 제어한다[4]. 선행 연구에서 HyDE는 웹 검색, 질의응답, 사실 검증과 한국어를 포함한 다국어 검색에서, CAD는 요약과 지식 충돌 과제에서, SCD는 다국어 RAG의 언어 이탈 과제에서 각각 효과가 보고되었다.

한국어 질의로 영어 논문을 다루는 RAG는 세 가지 과제를 함께 풀어야 한다. 검색에서는 한국어 질의와 영어 원문의 어휘 차이를 넘어 근거를 찾아야 하고, 답변 생성에서는 영어 근거의 내용을 한국어 답변에 충실히 반영해야 한다. 또한 모델이 영어 근거를 따라 영어로 답하는 언어 이탈(language drift)을 막아야 한다. HyDE는 검색 입력을, CAD는 근거 반영을, SCD는 출력 언어를 조정하므로 세 기법은 이 과제에 하나씩 대응한다. 선행 연구에서는 각 기법을 서로 다른 모델과 과제에서 따로 평가하였다. 그러나 문서 질의응답에서는 수치를 옮기는 질문, 과정을 설명하는 질문, 개념을 해석하는 질문처럼 질문마다 요구하는 작업이 다르고, 같은 기법도 질문의 종류에 따라 효과가 달라질 수 있다. 따라서 세 기법을 한 파이프라인에 함께 적용하고 질문 유형별로 결과를 비교해야 실제로 기법을 고르는 기준을 얻을 수 있다.

실험에는 영어 학술 및 기술 문서를 검색하여 한국어 답변을 생성하는 고정 파이프라인 Paper-RAG를 사용하였다. 같은 한국어 질문 60개에 HyDE, CAD, SCD의 적용 여부를 조합한 여덟 조건을 적용하였다(그림 1-1).

본 연구의 목적은 한국어 질의와 영어 문서를 다루는 RAG에서 HyDE, CAD, SCD와 그 조합의 효과가 질문 유형에 따라 어떻게 달라지는지 밝히고, 유형별로 적용할 기법을 제시하는 것이다. 이를 위해 여덟 조건의 원점수를 비교하고, 질문을 수치, 방법, 개념과 결과의 세 유형으로 나누어 같은 비교를 반복한 뒤, 점수가 크게 바뀐 질문의 검색 근거와 답변을 미적용 조건과 대조한다. 본 연구는 같은 파이프라인과 질문에서 세 기법과 조합의 이득과 비용을 질문 유형별로 제시하여, 한국어 질의로 영어 문서를 다루는 RAG에서 기법을 고르는 근거를 제공한다.

## 2.2 하이브리드 검색과 재정렬 [스타일=절(1.1)]

밀집 검색은 질의와 문서 구간을 임베딩한 벡터의 유사도로, BM25(Best Matching 25) 희소 검색은 두 텍스트의 어휘 일치로 관련 구간을 찾는다[5][6]. 한국어 질의와 영어 원문은 어휘가 대부분 다르지만, 논문명, 모델명, 데이터셋명, 수치처럼 두 언어에 같은 형태로 쓰이는 표기는 BM25의 검색 단서가 된다.

두 검색 결과는 가중 역순위 융합(weighted Reciprocal Rank Fusion, RRF)으로 결합한다[7]. 문서 d의 밀집 검색 순위와 BM25 순위를 각각 rank_dense(d), rank_BM25(d)라 할 때, 가중치 0.6과 0.4, 상수 k=60을 적용한 결합 점수는 다음과 같다.

[한글 수식 입력기 복붙용 — 최종 HWP에는 렌더링된 수식만 남김]

```text
RRF(d) = {0.6} over {k + rank_dense(d)} + {0.4} over {k + rank_BM25(d)}
```

융합한 검색 후보는 질의와 후보 구간을 한 쌍으로 입력받는 재정렬 모델의 관련성 점수로 다시 정렬한다. 재정렬 모델로는 CEDR(Contextualized Embeddings for Document Ranking)[8] 등이 있다. 생성 모델은 입력 내 위치에 따라 근거를 다르게 활용할 수 있으므로[9], 재정렬 순서는 답변에도 영향을 줄 수 있다.

## 2.3 가상 문서 임베딩과 검색 [스타일=절(1.1)]

HyDE는 입력 질의로 생성한 가상 문서를 임베딩하여 실제 문서 집합에서 유사한 문서를 검색한다. 가상 문서의 내용이 틀릴 수 있어도 답변과 비슷한 어휘와 문장 구조를 갖기 때문에, 짧은 질문을 그대로 임베딩할 때보다 관련 문서에 가까운 검색 입력을 얻을 수 있다. 가상 문서는 검색 입력으로만 쓰이고, 최종 답변의 근거는 검색한 실제 문서 구간이다(그림 2-2).

## 2.4 Context-Aware Decoding [스타일=절(1.1)]

CAD는 검색 결과를 포함했을 때와 제외했을 때의 다음 토큰 로짓을 가중 결합하는 디코딩 방법이다. 검색 결과를 넣었을 때 로짓이 크게 오르는 토큰일수록 검색 결과의 영향을 많이 받는다. CAD는 두 로짓의 차이를 키워, 모델의 사전 지식보다 검색 결과의 내용을 반영하는 토큰이 선택되도록 한다(그림 2-3).

지금까지 생성한 토큰열을 동일하게 두고, 검색 결과를 포함한 입력의 로짓을 z_ctx, 제외한 입력의 로짓을 z_noctx라 하면 CAD의 로짓은 다음과 같다. α는 검색 결과의 영향을 키우는 정도를 정하며, α=0이면 일반 디코딩과 같다.

[한글 수식 입력기 복붙용 — 최종 HWP에는 렌더링된 수식만 남김]

```text
z_CAD = (1 + alpha) z_ctx - alpha z_noctx
```

Shi 외는 요약 과제와 지식 충돌 과제(모델의 사전 지식이 입력 문서의 내용과 충돌하는 과제)에서 CAD가 입력 문서를 더 충실히 반영한다고 보고하였다. CAD는 토큰마다 검색 결과를 제외한 입력의 로짓을 한 번 더 계산하므로 생성 시간이 늘어난다.

## 2.5 Soft Constrained Decoding과 언어 이탈 [스타일=절(1.1)]

다국어 RAG에서는 질문과 다른 언어의 문서를 검색하면 답변이 검색 문서의 언어로 바뀌는 언어 이탈이 발생할 수 있다. Li 외는 이 현상을 분석하고, 디코딩 단계에서 목표 언어 토큰의 점수를 조정하는 SCD를 제안하였다. SCD는 어휘 집합을 목표 언어 토큰, 비목표 언어 토큰, 숫자나 기호 같은 중립 토큰으로 나누어 로짓을 조정한다(그림 2-4).

[그림삽입: FINALDOCS/FIGURES/LITERATURE/fig2_4_scd_independent.png | 권장폭=본문폭 75% | 정렬=가운데]

[그림 2-4] SCD의 토큰 그룹별 로짓 조정[4] [스타일=그림제목]

생성한 토큰 수가 Tstart 이상이 되면 목표 언어 토큰의 로짓 z_i에는 α를, 비목표 언어 토큰의 로짓에는 β를 곱하고, 중립 토큰은 그대로 둔다. 아래 식의 좌변은 조정된 로짓이다. 본 연구는 한국어를 목표 언어로 하여 원 논문의 곱셈식을 그대로 적용하였다. 이 식은 원시 로짓에 계수를 곱하므로, 로짓이 양수인 토큰과 음수인 토큰에서 점수가 변하는 방향이 반대가 된다.

[한글 수식 입력기 복붙용 — 한국어 목표 토큰]

```text
tilde z_i = alpha z_i
```

[한글 수식 입력기 복붙용 — 비목표 언어 토큰]

```text
tilde z_i = beta z_i
```

[한글 수식 입력기 복붙용 — 중립 토큰]

```text
tilde z_i = z_i
```

## 2.6 RAG 평가 [스타일=절(1.1)]

RAGAS는 RAG의 검색과 생성을 나누어 자동으로 평가하는 프레임워크다[10]. RAGAS가 제공하는 근거 충실도(faithfulness), 답변 관련성(answer relevancy), 문맥 정밀도(context precision), 문맥 재현율(context recall) 가운데 근거 충실도와 답변 관련성은 생성 답변을, 문맥 정밀도와 문맥 재현율은 검색 결과를 평가한다. 근거 충실도는 평가 모델로 쓰는 대규모 언어 모델(Large Language Model, LLM)이 답변을 주장 단위로 나누고 각 주장이 검색 결과에 근거하는지 판정하여 계산한다. 지표별 계산 방식은 5.2절에 정리하였다.

## 2.7 관련 연구와 본 연구의 위치 [스타일=절(1.1)]

Dense Passage Retrieval(DPR)[11]은 질의와 문서를 각각 임베딩하는 밀집 검색을, Fusion-in-Decoder(FiD)[12]는 여러 검색 구간을 디코더에서 결합하는 생성을 다룬다. Contrastive Decoding[13]은 두 모델의 출력 분포를 대조하며, CAD는 같은 모델에서 문맥을 포함한 입력과 제외한 입력을 대조한다.

RAPTOR[14]는 계층적 요약 검색을, Self-RAG[15]와 Adaptive-RAG[16]는 검색 필요성과 질문 복잡도에 따른 검색 전략을 다룬다. Zhao 외[17]와 Fan 외[18]는 구성 요소별 기법을 정리하였고, BEIR(Benchmarking Information Retrieval)[19]와 MTEB(Massive Text Embedding Benchmark)[20]은 검색과 임베딩을 비교하는 벤치마크다.

본 연구는 검색과 생성의 구성을 고정한 채 HyDE, CAD, SCD를 조합하고, 한국어 질문 60개의 유형별 점수를 실제 검색 결과와 답변에 연결한다. 표 2-1은 선행연구의 접근과 본 연구의 분석 대상을 정리한 것이다.

# 3. 시스템 설계 [스타일=장(1.)]

이 장은 실험 요구사항, 아키텍처, 실험 조건을 설명한다.

## 3.1 연구 및 실험 요구사항 [스타일=절(1.1)]

모든 조건에서 검색, 재정렬, 생성 모델과 청크(문서를 나눈 검색 단위) 분할, 후보 수의 상한, 생성 설정을 고정하고, 같은 한국어 질문 60개를 사용하였다. 질문마다 검색 결과, 생성 답변, 처리 시간과 파라미터를 저장하여 조건 간 결과를 질문 ID로 연결하였다.

## 3.2 아키텍처 설계 [스타일=절(1.1)]

Paper-RAG는 검색, 재정렬, 생성의 세 단계로 구성되며, 실행 순서는 4.2절의 그림 4-1에 제시하였다. 검색 단계에서는 BGE-M3 기반 밀집 검색과 BM25 희소 검색을 함께 사용한다. HyDE는 밀집 검색의 입력만 원질의에서 영어 가상 문서로 바꾸고, BM25와 재정렬에는 항상 한국어 원질의를 사용한다.

두 검색 결과를 가중 RRF로 결합하고 CrossEncoder로 재정렬한 뒤, 상위 5개 구간을 생성 모델에 입력한다. 생성 단계에서는 검색 결과 유무에 따른 원래 로짓의 차이를 쓰는 CAD를 먼저 적용하고, SCD는 CAD가 결합한 로짓에 언어별 계수를 곱한다. 두 기법은 생성 단계에만 작용하므로, HyDE를 적용하지 않은 조건에서 CAD와 SCD의 적용 전후 비교에는 같은 검색 결과가 쓰인다.

## 3.3 실험 조건과 비교 방법 [스타일=절(1.1)]

세 기법의 적용 여부를 조합하여 여덟 조건을 만들고, 모든 조건에 같은 질문 60개를 입력하여 생성 기록 480개를 얻었다. 표 3-1은 조건 번호와 기법별 적용 여부, 품질 평가에 사용한 검색 결과의 언어를 나타낸다. 조건 번호는 미적용, 단일 기법, 두 기법 조합, 세 기법 조합의 순서이며 5장의 모든 표와 그림에 같은 번호를 사용한다.

{{TABLE:T3-1_Conditions}}

SCD를 적용한 조건 4, 6, 7, 8은 답변이 대부분 한국어이므로 검색 결과를 쓰는 근거 충실도, 문맥 정밀도, 문맥 재현율을 한국어로 번역한 검색 결과로 평가하였고, 이 세 지표는 SCD 적용 여부가 같은 조건끼리 비교한다(5.2절). 한국어 문자 비율과 처리 시간은 여덟 조건 모두 저장된 답변과 실행 기록에서 같은 방식으로 계산하였다. 각 조건의 결과는 질문 ID로 연결하여, 같은 질문에서 두 조건의 점수를 비교하였다.

HyDE를 적용하지 않은 조건 1, 3, 4, 7은 질문마다 같은 검색 결과를 사용하였다. HyDE를 적용한 조건은 가상 문서를 조건마다 다시 생성하였으므로 검색 결과도 조건마다 달라질 수 있다. 예를 들어 HyDE와 HyDE+CAD의 최종 입력 구간이 같은 질문은 60개 중 18개였고, HyDE+SCD와 HyDE+CAD+SCD는 24개였다. 따라서 HyDE를 포함한 조건 사이의 차이에는 생성 제어의 차이와 검색 결과의 차이가 함께 들어 있다.

# 4. 프로그램 구현 [스타일=장(1.)]

이 장은 실행 환경, 처리 흐름, 실행 기록 방식을 설명한다.

## 4.1 시스템 환경 [스타일=절(1.1)]

모든 조건은 같은 검색, 재정렬, 생성 설정을 사용하였다. 표 4-1은 공통 설정과 기법별 파라미터를 정리한 것이다. 청크 분할과 입력 길이는 공백 기준 단어 수로 계산하였고, 생성 길이의 상한은 생성 모델의 토큰 수(최대 512개)로 정하였다.

{{TABLE:T4-1_Environment}}

재정렬에는 검색 질의응답 데이터셋 MS MARCO(Microsoft Machine Reading Comprehension)로 학습한 MiniLM CrossEncoder[M2]를 사용하였고, 한국어 원질의와 영어 후보 구간을 한 쌍으로 입력하였다. 선택한 5개 구간의 단어 수 합이 3,072단어를 넘으면 ContextCompressor를 적용하였다. ContextCompressor는 질의와 겹치는 단어의 비율로 문장 순위를 정하고, 구간마다 단어 수의 50% 안에서 상위 문장을 골라 원래 순서대로 남긴다. 평가 질문과 분리한 튜닝 질문 5개에서 문맥 재현율이 0.95 이상인 후보 설정을 비교하였다. 그중 근거 충실도가 가장 높은 설정을 선택하여 검색 후보와 재정렬 후보의 상한을 각각 8개, 최종 입력 구간을 5개로 모든 조건에 설정하였다. CAD의 α는 Shi 외가 요약 과제에 사용한 0.5로 고정하였다. SCD의 α=1.1, β=0.9, Tstart=5는 Li 외가 목표 언어의 일치와 문장의 자연스러움을 함께 고려하여 실험에 사용한 값이다[4].

## 4.2 시스템 구성 [스타일=절(1.1)]

Paper-RAG는 질의 하나를 검색 입력 구성, 검색과 재정렬, 답변 생성, 실행 기록의 순서로 처리한다(그림 4-1). 먼저 질의에 지정된 대상 문서의 밀집 검색 인덱스와 BM25 인덱스를 불러온다. HyDE를 적용하면 답변 생성에 쓰는 Mi:dm 2.0 Base Instruct로 한국어 질의를 영어로 번역하고, 번역문으로 영어 가상 문서를 생성하여 밀집 검색의 입력으로 쓴다. HyDE를 적용하지 않은 조건은 한국어 원질의를 그대로 쓴다.

검색 단계에서는 밀집 검색과 원질의를 쓰는 BM25 검색에서 각각 최대 후보 8개를 얻어 가중 RRF로 결합한다. 한국어 원질의로 BM25를 실행한 기록에서는 60개 질문 중 13개가 후보 0개, 3개가 2개, 44개가 8개였다. CrossEncoder로 후보를 재정렬하여 상위 5개 구간(이하 입력 구간)을 고른다. 고른 구간의 단어 수 합이 3,072단어를 넘으면 ContextCompressor로 압축한 뒤 생성 모델에 입력하고, 3,072단어 이내이면 그대로 입력한다.

생성 단계에서는 검색 결과와 질의로 생성 프롬프트를 만들고, 조건에 따라 CAD와 SCD의 로짓 처리기를 붙여 greedy 디코딩(매 단계에서 점수가 가장 높은 토큰을 고르는 방식)으로 답변을 생성한다. 마지막으로 검색 청크 ID와 재정렬 청크 ID, 최종 검색 결과, 답변, 처리 시간과 파라미터를 기록하며, 평가값은 질문 ID와 조건으로 이 기록에 연결한다.

## 4.3 시스템 구현과 실행 기록 [스타일=절(1.1)]

CAD는 토큰을 하나 생성할 때마다 같은 지시문에서 검색 결과만 뺀 입력의 로짓을 추가로 계산하고, 두 로짓을 2.4절의 식으로 결합한다. SCD는 생성한 토큰이 5개 이상이 되면 한국어 토큰과 비한국어 토큰의 로짓에 각각 α와 β를 곱한다.

생성은 질문 19개와 41개의 두 번으로 나누어 실행하였다. 각 실행은 조건 번호와 다른 순서인 미적용, CAD, SCD, CAD+SCD, HyDE, HyDE+CAD, HyDE+SCD, HyDE+CAD+SCD의 순서로 진행하였고, 한 조건의 질문을 모두 처리한 뒤 다음 조건으로 넘어갔다. 두 실행의 첫 질문인 미적용 질문 두 개는 각각 164.153초와 117.317초가 걸렸다. 이 시간에는 첫 추론의 준비 시간이 포함되므로, 처리 시간 비교에는 두 질문을 모든 조건에서 뺀 58개 질문을 사용하였다.

처리 시간은 모델과 검색 구성요소의 초기화가 끝난 뒤, 각 질문과 조건의 처리 시작부터 답변 생성과 기록용 메타데이터 구성이 끝날 때까지 측정하였다. HyDE를 적용한 조건에는 번역과 가상 문서 생성 시간이 포함되며, 평가 API 호출과 파일 기록은 측정이 끝난 뒤에 수행하였다.

그림 4-2는 수치 질문 하나에서 세 기법이 작동하는 방식을 저장된 실행 기록으로 나타낸다. 질문은 Mi:dm K 2.5 Pro 모델의 파라미터 수를 묻고, 정답 근거는 Mi:dm K 2.5 Pro 기술 보고서 2쪽의 32B parameters이다. HyDE가 생성한 가상 문서에는 13 billion parameters라는 틀린 수치가 들어 있었지만, HyDE 조건의 검색 결과에는 32B parameters 문장이 있는 실제 구간이 포함되었고 답변 관련성은 0.893에서 0.950으로 올랐다. 미적용 답변은 근거의 32B를 3.2 billion으로 옮겼고, CAD 답변은 32 billion parameters로 옮겨 근거 충실도가 0.571에서 0.778로 올랐다. 미적용 답변은 근거 문장을 영어 그대로 인용하였고, SCD 답변은 같은 문장을 한국어로 옮겨 인용하여 한국어 문자 비율이 0.638에서 0.828로 올랐다.
