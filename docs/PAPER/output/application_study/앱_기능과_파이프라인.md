# M-RAG 애플리케이션 기능과 파이프라인

이 문서는 논문과 별도로 M-RAG 애플리케이션의 코드상 기능과 실행 흐름을 정리한다. 논문의 여덟 조건 적용 실험은 연구 실행 경로의 결과이며, 아래 기능 전체의 성능이나 사용자 효과를 평가한 결과가 아니다. 현재 문서는 소스 검토 기준이고 실서비스 실행 검증 보고서는 아니다.

## 사용 흐름

사용자는 로그인 후 세션을 선택하고 문서를 등록하여 질의응답 작업 공간을 사용한다. 질문을 전달하면 서버가 대상 문서와 질문 유형에 따라 처리 경로를 선택하고, 검색 근거와 답변을 반환한다. 스트리밍 경로는 생성 중 내용을 점진적으로 전달한다.

```mermaid
flowchart LR
  U[로그인 및 세션 선택] --> P[문서 등록]
  P --> I[텍스트 추출 및 색인]
  I --> Q[질문과 대상 문서 선택]
  Q --> R[A–F 경로 선택]
  R --> G[검색 및 답변 생성]
  G --> V[답변과 출처 표시]
```

근거: frontend/src/App.tsx, backend/api/routers/papers.py, backend/api/routers/chat.py.

## 경로별 처리

| 경로 | 목적 | 주요 처리와 차이 |
|---|---|---|
| A | 일반 논문 질의응답 | 선택적 HyDE, 검색, 재정렬, 문맥 구성, 생성 |
| B | 절 중심 질문 | 질문에 맞는 절을 고려한 검색·문맥 구성 |
| C | 논문 비교 | 대상 문서별 검색을 수행하고 비교 문맥 구성 |
| D | 인용·참고문헌 질문 | 인용 추적과 관련 근거를 이용한 답변 |
| E | 요약 | 요약 목적에 맞는 문맥과 생성 지시 사용 |
| F | 퀴즈·플래시카드 | 학습 보조 질문과 답변 생성 |

근거는 backend/pipelines/pipeline_a_simple_qa.py부터 pipeline_f_quiz.py까지의 각 run 함수이다. 라우터는 학습된 최적 정책이 아니라 규칙 기반 서비스 선택기이다. A–F별 최적 기법 조합을 실험으로 확정했다는 의미는 아니다.

## A 경로의 구체적 흐름

선택적 HyDE → hybrid 검색 → 재정렬 → 추출형 문맥 압축과 길이 제한 → CAD·SCD 처리기 연결 → 답변 생성 → 후속 질문과 처리 기록 반환

HyDE를 사용할 때 질문 확장 모듈은 한국어 질문의 영어 번역과 가상 문서 생성을 수행한다. 검색에는 실제 색인의 논문 문단을 사용한다. 검색 결과가 없거나 처리에 문제가 있으면 코드의 상태와 반환 내용을 확인해야 하며, 빈 결과를 곧바로 해당 논문에 답이 없다는 증거로 해석해서는 안 된다.

## 논문 실험과 서비스의 차이

| 구분 | 논문 실험 | 서비스 |
|---|---|---|
| 실행 | experiments/runners/main_generation_executor.py | backend/api와 backend/pipelines |
| 목적 | 같은 질문의 조건별 비교 | 사용자의 작업 처리 |
| 자료 | 지정 논문 4편·질문 19개 | 사용자가 등록·선택한 문서 |
| DB | 연구용 SQLite | 운영용 PostgreSQL 구성 |
| SCD | reference_scd를 명시한 실험 실행 | 기본 A 경로는 모드를 따로 전달하지 않음 |
| 평가 | 보존된 답변과 점수의 대응 분석 | 전체 기능의 사용자 효과는 미평가 |

공통 SCD 처리기 함수의 기본 모드는 penalty_additive이며, 확인한 A 경로는 이 기본값을 사용한다. 따라서 reference_scd 조건의 논문 수치를 현재 앱의 기본 동작 성과로 제시하지 않는다. 이 문서 작성 과정에서는 서비스 설정을 변경하지 않았다.

## 검증이 더 필요한 부분

외부 인용·특허 API의 가용성, 실제 문서 업로드와 브라우저 질의응답, 다중 사용자 부하, 실패 후 복구, A–F별 답변 품질은 별도 실행 확인이 필요하다. 코드에 기능이 존재한다는 사실과 실제 사용자 작업이 안정적으로 완료된다는 사실을 구분한다.
