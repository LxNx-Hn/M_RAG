# 졸업논문과 발표 자료 작성 계획

## 확정한 범위

- 학부 졸업논문이며 한국어 질문과 영어 학술논문의 RAG 적용 실험을 다룬다.
- HyDE, CAD, SCD는 선행연구의 기법으로 명시한다. 본 연구의 기여는 해당 환경에 적용하고 효과와 한계를 비교한 데 둔다.
- 추가 생성·채점 실험은 계획하지 않는다. 기존 산출물의 확인과 재계산은 수행한다.
- 앱 기능과 A–F 파이프라인은 별도 문서로 작성한다. 논문의 설계·구현 대상은 비교 실험 프로그램이다.
- 제공한 HWP 양식의 장·절 구조와 스타일을 따른다. 사용자가 HWP에 옮기므로 편집 가능한 원고와 그림을 제공한다.
- 발표 시간과 논문 분량 제한은 없다. PPT는 초안 12장으로 구성하고 내용 검토에 따라 조정한다.
- 문장은 완결된 서술로 작성하고 기술 목록·과장된 성과·개조식 종결을 본문에서 피한다.

## 1단계 자료와 주장 확정

국·영문 기존 원고, 보정된 reference_scd 생성 자료, 최종 평가 보고서와 구현을 대조한다. 과거 설정과 서비스 기본값이 최종 실험에 섞이지 않도록 각 주장에 해당하는 근거를 연결한다.

확인할 사항은 실험 논문·질문 수, 대상 논문 지정 방식, 실제 HyDE 번역 경로, 고정 매개변수, 비교별 문맥 동일성, 평가 후처리와 표본의 한계이다. 출처가 불분명한 최초 질문 작성 과정은 사실 확인 항목으로 남긴다.

완료 기준: 본문에 사용할 수치·방법·한계를 정리하고 기존 산출물에서 재계산한 결과가 일치한다. 새 실험 필요성이 발견되면 자동 실행하지 않고 원고에 미치는 영향부터 설명한다.

## 2단계 목차와 논리 흐름 확정

| 양식 항목 | 작성 내용 |
|---|---|
| 초록 | 문제, 적용 환경, 기존 기법, 비교 실험, 결과와 해석 |
| 1. 서론 | LLM, RAG, 남은 문제, 교차언어 조건, 연구 목적 |

| 1.2 연구범위 | 선택된 영어 논문 대상, 기존 자료의 적용 실험 |
| 2. 이론적 배경 | RAG 잔여 오류와 HyDE·CAD·SCD의 선행연구 |
| 3. 시스템 설계 | 비교 실험 프로그램의 설계 |
| 3.1 요구사항 | 실험 수행자의 유스케이스와 명세 |
| 3.2 아키텍처 설계 | 자료·검색·생성·저장·평가의 연결 |

## 3단계 초록과 서론 교정

먼저 초록·서론을 한 묶음으로 제시한다. 교차언어는 RAG의 공통 문제에 추가되는 응용 조건으로 설명하고, CAD를 교차언어 전용 방법처럼 서술하지 않는다. 기법의 원 제안자와 본 연구의 적용을 구분한다.

JHARS는 필요한 근거가 제공되어도 생성 오류가 남는다는 문단에 한 편만 추가한다. 교차언어 검색 자체를 검증한 문헌으로 확대하지 않는다. 서론 첫 도식은 질문, 검색, LLM, 답변의 가로형 흐름에 적용 위치만 표시한다.

완료 기준: 사용자가 문제에서 목적까지의 흐름과 문체를 검토한다. 이 교정에서 확정한 표현을 나머지 장의 기준으로 사용한다.

## 4단계 본문과 그림 작성

이론적 배경은 각 선행연구의 문제·방법·본 연구와의 연결 순서로 작성한다. 설계와 구현은 비교 실험을 재현하는 데 필요한 내용만 포함한다. 필수 유스케이스와 명세, 구성도, 실행 순서는 실제 코드의 역할을 반영한다. 수식은 CAD와 SCD의 적용을 설명하는 데 필요한 범위로 제한한다.

실험 결과는 HyDE·CAD의 통제 비교, SCD의 한국어 출력, SCD의 후속 품질 평가 순서로 제시한다. 152개 답변과 19개 독립 질문을 구분하고 개선 미확인 결과도 그대로 기록한다.

완료 기준: 방법·설정·표·본문이 일치하고 결과보다 강한 결론이 없다. 도식은 본문 설명과 연결되며 표 제목은 위, 그림 제목은 아래에 둔다.

## 5단계 앱 별도 문서

사용 흐름, 기능 목록, A–F 경로, 주요 모듈과 자료 흐름을 정리한다. 코드상 기능과 실제 실행 검증을 구분한다. 실험의 reference_scd와 서비스 기본 경로의 차이도 기록한다. 서비스 코드는 변경하지 않는다.

완료 기준: 논문의 실험 결과를 앱 전체 기능의 성과로 오해하지 않고 기능별 코드 근거를 찾을 수 있다.

## 6단계 PPT 요약

논문 본문이 교정된 후 그 내용만 요약한다. 초안은 제목, 배경, 목적·범위, 선행연구, 설계, 구현, 실험 조건, 평가, HyDE·CAD 결과, SCD 결과, 한계, 결론의 12장이다. 출처와 설명은 발표자 메모에도 기록한다.

완료 기준: 논문과 수치·용어·결론이 일치하고, 모든 슬라이드를 렌더링하여 잘림·겹침·한글 표시를 확인한다. PPTX의 구조와 재열기 검사도 통과한다.

## 7단계 최종 검토와 인계

참고문헌 등장 순서, 표·그림 번호와 본문 참조, 국·영문 제목, 한글 UTF-8을 확인한다. 기존 결과 재계산 검사와 git diff --check를 수행한다. 본문 TXT, 교정용 Markdown, 그림, 앱 문서, PPTX와 발표 메모를 함께 제공한다.

HWP의 원본 스타일은 변경하지 않는다. 이름·지도교수·제출일·인준 정보와 최종 페이지 번호는 사용자가 입력한다. 실제 HWP로 이전한 후에는 페이지와 표·그림 배치를 다시 확인해야 한다.

## 완료 상태

계획의 산출물을 작성하고 전체 요청사항에 맞춰 재검토했다. `docs/PAPER/output/application_study/`에는 HWP 이전용 원고, 교정용 Markdown 원고, 도식 5개와 결과 조회 화면 1개, 앱 기능·파이프라인 문서, 14장 PPTX와 발표 메모가 있다. 원고와 PPT에는 최종 실험에서 사용한 구성과 결과만 남겼다. 실제 대조 내용은 `APPLICATION_STUDY_REVIEW.md`에 기록했다.

원고 검증 프로그램은 보존된 최종 산출물에서 수치를 다시 계산해 통과했다. HWP의 표지·인준 정보, 실제 페이지 번호와 최종 표·그림 배치는 양식에 옮긴 뒤 사용자가 확인한다. 기존 원고와 실험 산출물은 보존한다.
