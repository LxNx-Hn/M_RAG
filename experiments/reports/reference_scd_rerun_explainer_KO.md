# Reference SCD 재실험: 정말 쉬운 설명

이 문서는 숫자를 처음 보는 사람도 결론과 한계를 함께 이해하도록 쓴 설명서다.
정식 수치표와 세부 근거는
[`reference_scd_rerun_report_KO.md`](reference_scd_rerun_report_KO.md)에 있다.

## 30초 결론

1. 예전 SCD v1은 한국어 답변 유지에 거의 도움이 되지 않았다.
2. 논문 방식을 다시 구현한 `reference_scd`는 한국어 비율을 **크게 높였다**.
3. 다만 모든 언어 이탈을 없애지는 못했다.
4. 첫 `gpt-4o` 점수표는 SCD-on 문맥만 번역해 인과 효과를 말할 수 없었다.
5. 그래서 양쪽 조건을 같은 규칙으로 처리한 추가 평가를 했다. 근거 충실성 차이는
   아직 확정할 수 없고, 질문 관련성 저하는 다른 judge에서 확실하게 반복되지 않았다.

가장 안전한 한 문장은 다음과 같다.

> `reference_scd`는 한국어 언어 준수를 크게 개선했다. 더 공정하게 맞춘 추가
> 평가에서도 judge에 상관없이 확정되는 RAG 품질 차이는 없었다.

## 먼저 알아둘 말

| 말 | 쉬운 뜻 |
|---|---|
| config | HyDE, CAD, SCD를 켜고 끈 한 가지 실험 조합 |
| judge | 답변이나 문맥을 보고 RAGAS 점수를 매긴 LLM |
| null | judge 오류 등으로 점수를 얻지 못한 칸 |
| faithfulness | 답변의 주장이 검색 문맥으로 뒷받침되는지 보는 자동 점수. 사실성 전체나 모든 환각을 직접 증명하지는 않음 |
| answer relevancy | 답변이 질문에 얼마나 직접 관련되는지 보는 점수 |
| context precision | 검색 문맥 중 질문과 정답에 유용한 문맥이 앞쪽에 잘 배치됐는지 보는 점수 |
| context recall | 정답의 내용을 검색 문맥이 얼마나 포함하는지 보는 점수 |

중요한 차이가 있다. `answer_relevancy`는 문맥을 보지 않는다. `context precision`과
`context recall`은 생성 답변을 보지 않는다. `faithfulness`만 생성 답변과 문맥을
함께 본다. 이 프로젝트는 RAGAS 0.2.15의 이 정의를 사용했다.

## 무엇을 고쳤나

예전 `penalty_additive` v1은 비한국어 토큰에 고정값 `-0.3`을 더하는 방식이었다.
목표 언어를 따로 조정하지 않았고, 생성 초반의 완충 구간도 없었다.

`reference_scd`는 참고 논문의 세 가지 규칙을 재현했다.

- 목표 언어 토큰: raw logit에 `alpha=1.1`을 곱함
- 중립 토큰: 그대로 둠
- 방해 언어 토큰: raw logit에 `beta=0.9`를 곱함
- 처음 `Tstart=5`개 생성 단계: 제약을 적용하지 않음

논문은 이를 boost와 penalty로 설명한다. 다만 실제 코드는 **확률이 아니라 raw
logit**에 곱한다. 음수 logit에는 1.1을 곱하면 값이 더 작아질 수 있고 0.9를 곱하면
더 커질 수 있으므로, “모든 한국어 토큰 점수를 무조건 올리고 영어 토큰을 무조건
내린다”라고 단순화하면 틀리다. 정확한 표현은 “논문의 raw-logit 스케일링을 그대로
적용했다”이다.

## 한국어 비율은 어떻게 셌나

이 프로젝트의 한국어 비율은 다음과 같다.

```text
한글 문자 수 / (한글 문자 수 + 영문 알파벳 수)
```

숫자, 공백, 문장부호는 분모에서 빠진다. 따라서 “전체 문자 중 한글 비율”은 아니다.

## 검증된 언어 결과

SCD를 제외한 나머지 조건이 같은 76쌍을 비교했다.

| 항목 | 결과 |
|---|---:|
| 평균 한국어 비율 차이 | **+0.2203** |
| SCD-on에서 증가 / 감소 / 동일 | **68 / 3 / 5** |
| 기준 0.5 미만이던 답변의 회복 | **15/26** |
| 기준 0.7 이상에서 0.65 미만으로 떨어진 심각한 손상 | **0/20** |

이것은 강한 개선이다. 하지만 “완전 해결”은 아니다.

- SCD-on 답변 76개 중 12개는 여전히 한국어 비율 0.5 미만이었다.
- 76쌍 중 3쌍은 SCD-on 비율이 오히려 낮아졌다.
- `0/20`은 위에 적은 **특정 임계값 손상**이 없었다는 뜻이지, 어떤 감소도 없었다는
  뜻이 아니다.

이 언어 결과는 생성 텍스트에서 직접 계산했기 때문에 LLM judge와 무관하다.
또한 검색 문맥이 byte 단위로 모두 같은 HyDE-off 38쌍만 보아도 평균 차이가
`+0.2198`이므로, 핵심 언어 개선은 HyDE 검색 변동 없이도 유지된다.

## `gpt-4o` 점수표는 무엇을 보여주나

152개 샘플, 8개 config, config당 19개를 채점했고 4개 지표 608칸이 모두 채워졌다.

| SCD-on과 SCD-off의 평균 차이 | 값 |
|---|---:|
| faithfulness | -0.0480 |
| answer relevancy | -0.0571 |
| context precision | +0.0300 |
| context recall | -0.0658 |

이 숫자는 실제 저장된 점수표에서 정확히 계산된 값이다. 문제는 **원인 해석**이다.
현재 설계로는 “SCD가 세 지표를 나쁘게 만들었다”라고 결론 내릴 수 없다.

## 왜 인과 결론을 못 내리나

### 1. SCD-on 문맥만 번역했다

SCD-on 76개 문맥만 한국어 번역을 거쳤고 SCD-off 문맥은 영어 원문 그대로였다.
즉 SCD 여부와 번역 여부가 항상 같이 움직인다. 점수 차이가 SCD 때문인지 번역
때문인지 분리할 수 없다.

### 2. SCD-off 답변도 대부분 영어가 아니었다

SCD-off 답변 76개 중 50개가 이미 한국어 비율 0.5 이상이었다. 따라서
“SCD-off는 영어 답변 대 영어 문맥, SCD-on은 한국어 답변 대 한국어 문맥”이라는
설명은 사실이 아니다.

### 3. 정답 기준문은 영어로 남았다

질문은 주로 한국어, SCD-on 문맥은 번역된 한국어, 정답 기준문은 영어였다.
특히 context precision과 context recall은 이 언어 조합의 영향을 받는다.

### 4. 번역 성공은 구조 성공이었다

번역 도구는 chunk 개수와 비어 있지 않은지 등을 검사했지만 실제 한국어 번역인지
검사하지 않았다. 번역된 SCD-on chunk 380개 중 20개에는 한글이 없었고, 한 레코드의
5개 chunk는 성공 표시가 붙었지만 영어 원문과 완전히 같았다.

### 5. 일부 검색 문맥도 달랐다

76개 SCD on/off 쌍 중 원래 검색 문맥이 완전히 같은 것은 51쌍이었다. HyDE-off는
38/38이 같았지만 HyDE-on은 13/38만 같았다. 나머지 25쌍은 SCD 외에 검색 내용도
달랐다.

따라서 이 패널은 **SCD-on 문맥 번역 민감도 분석**으로는 유용하지만, SCD만의 품질
효과를 증명하지 않는다. 특히 context precision과 context recall은 생성 답변을
보지 않으므로 디코더인 SCD의 품질 효과로 해석하면 안 된다.

## 더 공정하게 맞춘 추가 평가는 무엇을 보여주나

앞의 문제를 줄이기 위해 HyDE-off 결과만 따로 다시 평가했다.

- SCD를 제외한 검색 문맥이 완전히 같은 38쌍만 사용했다.
- SCD-off와 SCD-on 모두에 같은 번역·검사 규칙을 적용했다.
- 영어로 맞춘 패널과 한국어로 맞춘 패널을 둘 다 만들었다.
- 점수를 보기 전에 입력을 확정하고 SHA-256 해시를 기록했다.
- 76개 답변에 두 지표를 적용한 패널 두 개, 총 304칸을 모두 채웠다.
- 같은 질문에서 나온 두 CAD 조건을 한 묶음으로 보고 10,000회 다시 뽑아 95%
  범위를 계산했다.

결과는 다음과 같다. 대괄호는 실제 차이가 있을 법한 95% 범위다. 이 범위에 0이
들어가면 좋아졌는지 나빠졌는지 아직 확정하기 어렵다.

| 지표 | 영어로 맞춘 평가 | 한국어로 맞춘 평가 | 쉬운 판정 |
|---|---:|---:|---|
| faithfulness | +0.0071 [−0.0596, +0.0714] | −0.0283 [−0.1044, +0.0510] | 둘 다 0 포함: 방향 미확정 |
| answer relevancy | −0.0910 [−0.1725, −0.0240] | −0.0752 [−0.1501, −0.0138] | 둘 다 0 아래: 저하 가능성 |

즉 “SCD가 근거 충실성을 좋아지게 한다”거나 “나쁘게 한다”는 답은 아직 없다.
반면 질문에 직접 답하는 정도는 두 언어 평가에서 모두 낮아졌다. 특히 CAD를 함께
켠 19쌍에서 두 언어의 범위가 모두 0 아래였다. 이 불편한 결과도 그대로 보존한다.

여기서 멈추지 않고, 번역에는 쓰지 않은 고정 `gpt-4.1-2025-04-14` judge로 같은
304칸을 다시 채점했다.

| 지표 | 영어 교차 채점 | 한국어 교차 채점 | 쉬운 판정 |
|---|---:|---:|---|
| faithfulness | −0.0579 [−0.1322, +0.0060] | −0.0326 [−0.0997, +0.0226] | 둘 다 0 포함 |
| answer relevancy | −0.0327 [−0.0851, +0.0129] | −0.0356 [−0.1149, +0.0315] | 둘 다 0 포함 |

평균은 여전히 음수지만 범위에 0이 들어간다. 즉 첫 judge에서 보인 “질문 관련성
저하가 확실하다”는 강한 판정은 다른 judge에서 반복되지 않았다. 이것이 최종 결과다.

그래도 **SCD가 인과적으로 관련성을 낮춘다고 확정하면 안 된다.** 이미 생성된 답변을
나중에 번역해 평가했고, 두 judge 모두 OpenAI 계열이며, 원래 질문은 19개뿐이고
한국어 패널에서 실제 번역된 답변 수도 SCD-off 23개와 SCD-on 11개로 달랐으며,
사람 평가는 없었다. 따라서 현재 결론은 “한국어 유지 효과는 강하지만 judge에
강건한 RAG 품질 차이는 없으므로 배포 전에 사람 평가가 필요하다”이다.

이 과정은 높은 점수에 맞춘 것이 아니다. 정규화 코드는 RAGAS 점수 파일을 읽지 않고,
언어·숫자·인용·문맥 동일성 규칙만 검사한다. 영어 입력 해시는
`8fba280f...f45c`, 한국어 입력 해시는 `d1c37e24...0ee9`로 채점 전에 고정됐다.

## NIM과 `gpt-4o`는 어떻게 구분하나

- 원래 Phase 8 행렬은 NVIDIA NIM judge로 채점했다.
- `reference_scd` 트랙의 NIM 시도는 보고된 실행 기록상 60시간 이상 진행했지만
  수렴하지 못했다.
- 이후 `gpt-4o`가 0/608 null의 완전한 패널을 만들었다.
- 두 judge의 절대 점수는 서로 직접 비교하지 않는다.
- Alice 원격 로그는 정리 과정에서 제거되어 NIM 시간과 중간 null 수치는 현재 로컬
  저장소에서 독립적으로 재현할 수 없는 보고서 기반 provenance다.

## 논문과 발표에 어떻게 쓰면 되나

써도 되는 표현:

> `reference_scd`는 직접 한국어 비율을 평균 +0.2203 높였고, 76쌍 중 68쌍에서
> 개선했으며, 0.5 기준 언어 이탈 26개 중 15개를 회복했다.

반드시 조건을 붙여야 하는 표현:

> `gpt-4o` 민감도 패널에서는 네 지표가 각각 -0.0480, -0.0571, +0.0300,
> -0.0658 차이를 보였다. 다만 SCD-on-only 문맥 번역과 검색 변동이 섞여 있어
> 이를 SCD의 인과 효과로 해석하지 않는다.

추가 평가까지 반영한 표현:

> 대칭 `gpt-4o` 패널에서는 answer relevancy가 낮았지만, 고정 `gpt-4.1` 교차
> judge에서는 영어와 한국어 모두 95% 범위가 0을 포함했다. 따라서 확실한 품질
> 비용으로 판정하지 않는다.

쓰면 안 되는 표현:

- “SCD가 언어 이탈을 완전히 해결했다.”
- “SCD가 환각을 줄였다.”
- “SCD가 RAG 품질 세 지표를 확실히 악화시켰다.”
- “0/20이므로 어떤 답변도 나빠지지 않았다.”
- “faithfulness가 곧 사실성 전체 또는 모든 환각이다.”

## 배포 판단

이 표본은 config당 19개, 한 번의 생성 실행이며 신뢰구간·통계적 유의성 검정·사람
평가가 없다. 따라서 `reference_scd`는 한국어 유지가 중요한 기능에서 검토할 수
있지만, 어떤 config를 운영 기본값으로 확정하기 전에 해당 서비스 질의로 품질을
따로 검증해야 한다.

이번 추가 평가로 동일 검색 문맥, 양쪽 조건의 같은 정규화 규칙, 한국어 검사,
bootstrap까지는 완료했다. 인과적 RAG 품질 결론까지 내려면 다음이 더 필요하다.

1. 이미 생성된 답변을 번역하지 않는 사전 설계 또는 원언어 평가로 재현한다.
2. OpenAI가 아닌 제공자의 judge로도 교차 채점한다.
3. 더 많은 독립 질문을 사용한다.
4. 조건을 숨긴 사람 평가를 함께 수행한다.
